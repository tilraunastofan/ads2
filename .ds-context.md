# ads2 for design-superpowers

The design system lives in code, not Figma. There is no Figma library; do not
run the Figma setup or ask for one.

## Sources of truth (read before reviewing or designing)

- `docs/design-system.md`: brand book and every UI rule. It overrides the
  suite's own style recipes, tokens and checklists.
- `tokens/tokens.json`: colours, type, spacing, radii. `assets/css/arion-theme.css`
  is generated from it by `task theme`; never edit the CSS.
- `docs/components/`: one file per shadcn-templ component and how to use it.
- `docs/patterns.md`, `docs/htmx-patterns.md`: page patterns (`patterns.Shell`,
  `PageHeader`, `Stat`, `DataCard`, `StatusBadge`) and htmx recipes.
- "Rules for UI work in this repo" in `CLAUDE.md`.

## How to report

- Polish mode: report real defects (accessibility, hierarchy, rule breaks,
  inconsistent naming). A finding that conflicts with an approved rule (serif
  titles at 600, 10px card radius, Lucide stroke 2, navy dark surfaces,
  sentences with periods, one primary button per view) is a **suggestion for
  the design-system owner**, not a defect, and is never changed in code.
- Never propose new components, hex values or Tailwind palette colours. A gap
  goes to the owner as a component request.
- Mechanical rules are already enforced by `task check`; don't re-report what
  it would fail on, report what it can't see.
- Judge dark mode from CSS variables under `.dark` on `<html>`, not screenshots
  (Dark Reader may be active).
